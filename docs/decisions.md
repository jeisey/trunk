# Decisions and assumptions

Material, reversible decisions made without asking. Newest at the bottom.

1. **Name.** "Trunk" with the tagline "A little help for the next hour." The repository had no existing name. This is a working name, not a trademark or domain claim.
2. **Stack.** Vite 8 + React 19 + TypeScript 6, plain CSS, Zod 4 for the content contract and runtime validation of shared/stored data, Vitest 5, Playwright 1.63 (pinned to match the pre-installed Chromium build). No CSS framework, router, state library, or compression library.
3. **Single authority for types.** Zod schemas in `src/content/schema.ts`; TS types via `z.infer`; JSON Schema generated to `docs/schema/content.schema.json` on every content build.
4. **Scripts run with Node's built-in type stripping** (Node ≥ 22.18), so imports use explicit `.ts` extensions and only erasable TypeScript syntax (`erasableSyntaxOnly`). Avoids adding `tsx`/`ts-node`.
5. **Age canonical unit = whole days.** 1 week = 7 days; 1 month = 365.25/12 = 30.4375 days rounded to the nearest day; years = 12 months. The same conversion is used for content bounds and entered ages, so "4 months" compares exactly against `4m`. Ranges are half-open `[min, max)`. Supported 1 week to under 60 months.
6. **Slider stops are non-uniform:** weekly 1–12 weeks, then monthly 3–59 months (69 stops), plus −/+ stepper and typed input.
7. **Content is JSON, one file per workstream,** merged and validated at build time into `src/generated/catalog.json`, which is bundled (no runtime fetch, no scraping).
8. **Supervision is modelled as data that drives feasibility:** participation (leads/joins/watches), proximity (holding/arms-reach/same-room), hands-on (continuous/intermittent/none), minimum adults, shareable, and a concrete space constraint. One-adult parallel feasibility is a categorical function (`src/lib/supervision.ts`) used by both the validator and the planner.
9. **Two-child suggestions come only from curated mixed-age recipes.** Compatibility is never inferred from overlapping ages or effort tags. The feasibility function double-checks every parallel recipe at build time.
10. **Tummy-time position is explicit on each tummy-time record.** Only `floor` counts as a flat surface. The app never credits chest/lap/carry/propped minutes toward a flat-surface target.
11. **The reported CHOP instruction** (60 minutes a day on a flat surface for this family's 4-month-old, elevated positions excluded) is preserved as reported, individualized clinical guidance. It is not a public CHOP protocol, it is not verified from a public document, and the app never applies it to every baby.
12. **Energy/attention is one control** with four levels: busy nearby (you can watch but not play), low, some, plenty. "Busy nearby" admits only activities with `watches` + `same-room` + no hands-on + shareable + no water/heat/food/traffic hazards.
13. **Media** appears only when the record's age floor is met and the parent chose the busy-nearby or low-energy context; it is never a planner default and is capped per plan.
14. **Routing uses the URL hash** (`#/…`) so GitHub Pages needs no rewrites; Vite `base` is `./` so the build works under any repository path.
15. **No service worker, analytics, external fonts, or runtime network calls** in v1.
16. **Runtime validation uses `zod/mini`; the full Zod API runs only at build/test time.** Vocabularies live in a Zod-free module (`src/content/vocab.ts`). This cut the initial bundle by ~20 KB gzip.
17. **Evidence loads lazily.** Activities, pairings, and starter plans ship in the initial bundle; claims and sources (`src/generated/evidence.json`) load in a separate chunk, prefetched when the browser is idle and on any page that shows sources. Keeps initial JS well under 200 KB gzip as the catalog grows.
18. **Midday sun rule for babies under 6 months.** Following AAP's 2026 *Baby Sunburn Prevention* page, the planner never schedules an outdoor, sun-exposed activity for a baby under 6 months between 10 a.m. and 4 p.m., and says so in the plan notes. Shaded walks outside that window remain, with clothing/shade/heat notes on the activity.
19. **One child of two.** With two children, "Who's this for?" can target one child (ideas and plans for that child only) with a visible reminder that the other child must be asleep, safely contained in view, or with another adult. Empty two-child results offer this as a one-tap option.
20. **Default first-visit age is 6 months.** Any default is arbitrary; mid-infancy shows a representative set. Ages and filters (never names or dates) are remembered in this browser for convenience.
21. **Share-link budget is 2,000 characters** for the whole URL. Typical plans use 150–400. Decoding is capped at 6,000 input characters and 16 KB decompressed. Over-budget plans fall back to images or a downloadable plan file that imports through the same checks.
22. **The local test server gzips text assets** to match GitHub Pages; lab performance is measured that way (`scripts/perf-lab.mjs`).
23. **Accessibility scan:** `@axe-core/playwright` (dev only) runs WCAG 2.1 A/AA rules on every main view and dialog, in addition to keyboard, zoom, and touch-target checks.
24. **Hot playground surfaces** are tagged `sun-weather` with a safety note rather than `heat`; `heat` is reserved for stoves, ovens, and hot liquids, which are never shareable.
25. **Independent review fixes (2026-10-29).** All blockers and majors in `docs/review/content-review.md` were fixed; see "Resolution" in that file. Notable rules added to the validator: single-child records may not add a second child (two-child setups live only in curated recipes); together recipes with water/heat/food/traffic need `adult.handsOnFor: "both"`; records with serious hazards must lead with a sourced safety note (it is the one shown on cards and images).
26. **Time-of-day rules are shared** (`src/lib/timeRules.ts`): the planner avoids, and the plan editor and share preview flag, outdoor time for babies under 6 months that overlaps 10 a.m.–4 p.m. (whole segment, not just its start) and outdoor-only ideas between 8 p.m. and 6 a.m.
27. **Food is never auto-added to a plan.** Snacks remain in the finder, starter plans, and "+ Activity"; a snack is a parent's choice, not a filler.
28. **The public tummy-time guide no longer names the family's hospital.** It describes "a hospital neonatal team" and keeps the individualized framing; `docs/research.md` and decision 11 preserve the full reported context (CHOP).
29. **Tummy-time tally** says "up to N min planned" and asks parents to count only minutes actually spent on the tummy, so a plan never overstates progress toward a clinician's flat-surface target.

## Refinement: timing, routines, mobile UI, brand (2026-10-29)

30. **Timing is reviewed data, not inferred.** Every activity and recipe has a reviewed `timing.stimulation` (`settling`, `gentle`, `lively`, `variable`). It is not derived from `intents` (chest and lap tummy time are tagged "calm" but still carry the HSE feed rules). `variable` means "depends, or not assessed" and never counts as calm or cleared.
31. **Timing rules are small records keyed to routine events** (milk feed, meal, nap; before measured from the event's start, after from its end). Each says whether its guidance and its window come from a source or are Trunk's editorial convention. HSE's "avoid tummy time just before or after feeds" has no number in the source, so Trunk's 15/30-minute windows are labelled editorial. Condition-limited rules (spit-up) are advisory because Trunk never records conditions: they are shown and ranked lower, never used to exclude.
32. **One evaluator** (`src/lib/timing.ts`) serves the finder, planner, editor, shared previews, and image export. Windows are measured directly between event and activity, so a break in between never resets a post-feed window. Any concern outweighs any preference. Missing information never produces a "safe after feeding" label.
33. **Before-nap and after-waking rules are editorial preferences** (settling activities "Good for winding down", lively ones "Better earlier", gentle first after waking). They rank; they never prohibit, never promise sleep, and never imply a required waiting time. No wake windows, nap lengths, or feeding intervals are prescribed.
34. **"Just fed" and "Nap soon" are momentary.** They are independent toggles per child, kept in memory only: not in preferences, session storage, plans, or shares. A refresh starts clean.
35. **Plan format v2** adds typed routine blocks (nap, milk feed, meal, snack) with anchored times, locked entries, and alongside tracks. A v1 plan is a v2 plan with none of these, so migration keeps every entry and timeline position; a v1 custom entry labelled "Nap" stays custom text.
36. **Anchors are offsets from the plan's start.** Changing the start moves the whole plan, routines included; editing an earlier entry never moves a routine. Anything that runs into an anchored entry is a conflict with local repairs (shorten, move after, move the routine explicitly, remove), never a silent reshuffle.
37. **Overlap is explicit only.** An entry runs alongside a routine block (for the other child) only when marked `along`; nothing else overlaps. Wall-clock time is the union of occupied intervals. During a routine the adult is busy (milk feed; nap while settling; nap with unknown availability or "staying with them") or undivided (meal/snack); one adult can then supervise only busy-nearby-compatible indoor play, or nothing during a meal. Settling a baby, feeding, and supervising eating are not free adult time.
38. **The planner fills around parent anchors** with a bounded, phase-aware look-ahead per gap and never invents a routine block, infers a nap from the window ending, or auto-adds food activities. A parent-placed meal block is a different thing from a food activity.
39. **Formats are versioned independently:** plan v2, storage envelope v2 (v1 text kept once in `trunk.plans.v1`), session draft migrated with its snapshot so a clean draft stays clean, share links `2z.` (v1 links still open), plan files `trunkPlan: 2` (v1 files still open).
40. **Brand kit assets are used as supplied.** Masters live unchanged in `public/brand/`; small palette PNG renditions (1–8 KB) serve the header, favicons, touch icon, and image export. Colours come from one module (`src/brand.ts`) mirrored by CSS tokens and checked by a test. Forest is text and primary actions; sky is accent and soft backgrounds with forest text.
41. **General caveats live on About.** Screens keep short functional labels, activity-specific safety, and contextual timing reasons; clinical-review status, general medical limits, evidence method, storage explanations, and how timing cues work are on `#/about`.
